# Terms-of-service check of the GitHub Actions collectors (2026-10-10)

Scope: the 10 workflows in `.github/workflows/` and every outside API they call on a schedule.
Sources: GitHub Terms for Additional Products (Actions section), GitHub Acceptable Use Policies,
Solana cluster docs (public RPC limits), Hyperliquid API rate-limit docs. Read 2026-10-10.

## The GitHub rule that matters

GitHub's Actions terms say Actions should not be used for "any activity that places a burden on our
servers, where that burden is disproportionate to the benefits provided to users (for example, don't
use Actions as a content delivery network or as part of a serverless application, but a low benefit
Action could be ok if it's also low burden)", and, on GitHub-hosted runners, "any other activity
unrelated to the production, testing, deployment, or publication of the software project associated
with the repository". Misuse can lead to "disabled repositories, or account suspension or termination".
The Acceptable Use Policies separately bar "excessive automated bulk activity".

Public repos get unlimited free minutes, but that does not exempt them from these rules.

## Could this have caused the StaticPush7217 suspension?

Plausibly yes, though GitHub gave no reason and this is inferred. The old account started the 24/7
recorder (uploading ~40 MB/h to Releases) at 2026-10-09 20:33 UTC and the 24/7 five-minute
autotrade loop around 2026-10-10 00:24 UTC, alongside ~170 commits a day to one repo. Two
always-on jobs plus bulk release uploads on a days-old setup is exactly what GitHub's automated
Actions-abuse detection looks for. The same workflows are now running on wardalexander368-sudo, so
the same risk carries over.

## Outside APIs

- **Solana public RPC** (`api.mainnet-beta.solana.com`): limits 100 req/10 s per IP, 40 concurrent
  connections, 100 MB/30 s; "not intended for production"; may block without notice. The recorder's
  long-lived websocket with many pool subscriptions is the heaviest user. Worst case is an IP block,
  not an account action. Fine for occasional calls (fees step, reconcile).
- **Hyperliquid info API**: 1200 weight/min per IP. Our collectors use a few hundred per run.
  The candle backfill could briefly exceed it on a first run; now paced at 1.5 s per coin.
  Note for going live: Hyperliquid's terms bar restricted persons and jurisdictions (including the US)
  and GitHub's runners sit in US data centres. Reading public data is fine; sending real orders from a
  runner should be checked against those terms first.
- **GeckoTerminal** (free, ~30 calls/min): the cohort job sleeps 2.2 s between pages. Fine.
- **DefiLlama, Jupiter (lite-api quotes), Kamino, Jupiter perps-api**: a few calls an hour. Fine.
- **PumpPortal, Jupiter swap**: only in live mode, which is off. Nothing called now.
- **GitHub API** (health, pumpflow-live): uses the job token, low volume. Fine.

## Recommendations (disabling needs AJ's say)

1. **Disable `recorder` now.** Pump.fun buying is closed in every form; its remaining user is the F1
   forward test (to 2026-10-19) and `pumpflow-live`. If that data is still wanted, record it on a
   machine we control, not on Actions.
2. **Move `autotrade` to a plain hourly cron** (one run per job, no self-chaining loop). The perps
   strategies step daily or weekly, so hourly loses nothing for them; only the dip rule wants 5 min,
   and it is closed for real money. That also cuts bot commits from ~290/day to ≤24.
3. Keep everything else. Consider batching the small collectors' commits if commit count grows.
